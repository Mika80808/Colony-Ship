# 星際港場景物件流程

一句話：**物件單獨生、正面俯視；位置和大小由使用者在 PSD 排；擺進地圖時照「圖層與碰撞規則」。**

整張場景（底圖、牆、門、碰撞）的流程見 `.claude/skills/generate2dmap/`，這份接在它的第 6 步。目前的範例是醫療室藥局（2026-10-26）：`tools/art/medical_objects.py`（物件表、拆圖、擺放、互動）、`tools/art/medical_base_v9.py`（寫 map.json）。切圖一律用共用工具 `tools/art/cut.py`，新場景只要寫 `tools/art/<場景>_objects.py` 的資料。工程區的物件要重做，`engineering_objects.py` 是舊流程，不要照抄它的物件。

## 視角與設計

- **正面俯視（使用者定）**：物件正面跟畫面平行、上方露出頂面，左右側面都不能出現；不斜放、不旋轉、不等角。斜的物件放不進地圖，直接作廢。矮的東西（桌子、櫃台、床）主要看到頂面，高的東西（櫃子、機台）看到正面加頂面。prompt 寫法見 `starport-asset-gen` 第二節範本的 CAMERA 段。
- **prompt 一律照 `starport-asset-gen` 第二節的範本填**（唯一正本，這裡不另寫）：規則只有鏡頭、燈光、地面三條，物件風格靠第四節的場景主題與關鍵字，材質、顏色讓模型自由設計。
- 物件描述要寫出它做什麼、科技感表現在哪（整合式螢幕、全息投影、會動的機構）、哪裡會動，並列禁止項：no exposed bolts or rivets, no chunky bumper feet, no ribbed hoses, no exposed wiring, no boxy old monitors, no yellow-black stripes（工程區 batch20 只寫 clean / no rust，畫出乾淨但中古的東西，整批作廢）。
- **不附風格參考圖**（2026-11-22 使用者定）：附了以後每件物件都長得一樣。`tools/art/<場景>/style_ref/` 的圖只給人看、討論方向用，不交給生圖模型；要借它的點子就用文字描述。
- **不給白膜**（使用者定）：不要附程式白模、實心灰色剪影或形狀參考圖來定造型、視角或外形。模型會照描，畫出來又平又空（2026-11-22 L 型吧檯附了 L 形灰色剪影，成品像向量小圖示）。形狀、尺寸、鏡頭一律用文字寫（佔幾格、長軸朝哪、看得到哪幾個面）；尺寸框只用來排多件物件的位置，且只畫細框線。

## 流程

### 1. 底圖（只有地面）
- 地板、牆、門等不動的結構做成底圖（`public/assets/<場景>/ground.webp`）。底圖**不能**有家具、機台、可互動或要排前後的東西。使用者自己改底圖時，改的檔案在 `tools/art/<場景>/ground.webp`。
- 門、會動的東西、蓋在角色上的前景（牆簷、欄杆）另外分層。

### 2. 規劃分區與物件清單
- **依這個地方的功能和動線分區，不要照搬別的場景的格局**（工程區曾經不自覺抄了溫室的「中間主角＋左右對稱」）。先問：東西從哪進來、在哪處理、人在哪休息；要參考真實場所怎麼布置的（例：大醫院的藥局）先查。
- 清單寫在 `<場景>_objects.py`：每件的名稱、大約佔地與高矮、用途、有沒有互動、會不會動（要動的零件要另外一層）。

### 3. 整區設計稿（選用）
- 一區物件很多、要先看整體感時，可以在底圖上畫一張整區設計稿（藥局 `raw/props_pharmacy_area_v3.png`），給使用者確認造型和配置。
- 設計稿**只當設計參考**：不切、不當底圖，物件一律在第 4 步單獨重生。

### 4. 單件物件
- **以房間為單位、固定比例（2026-10-26）**：一個房間的物件畫在同一張，**畫布固定一格 128 px**（12 × 8 格的房間剛好 1536 × 1024；更大的房間拆兩張），附一張「尺寸框」參考圖（洋紅底、灰框標出每件的位置與大小：寬＝幾格 × 128，高＝畫出來的高度），prompt 逐件寫「在 x…、y… 的灰框裡」。切圖時整張用同一個倍率縮（`<場景>_objects.py` 的 `SHEET_SCALE`，128 → 2 倍圖 96 是 0.75），不各自縮到指定寬度。
  - 為什麼：遊戲裡的線寬＝生圖線寬 × 縮小倍率。物件各自生（每件都畫滿畫布）再各自縮，小東西縮得多、描邊變細，同一間房粗細不一、比例也亂（使用者指出）。固定比例後描邊一致、大小一開始就對（診間實測：每件比框大 5–10%，一致）。
  - 物件之間留空隙，不畫成擺好的整間（整區畫好再切會黏在一起、背後缺一塊）。位置還是使用者在 PSD 排。
  - 寫法照 `starport-asset-gen` 第二節範本，`Draw ONE object only` 改成逐件列出（每件：是什麼、幾公尺、關鍵字）；附圖只有細框線尺寸框（重畫同一件時可加舊圖，寫明只看是什麼東西）。
- 候選階段（造型還沒定時）可以先生一張 8 件的候選表給使用者挑，挑完再照上面整房生定稿。
- 第 3 步的整區設計稿（有的話）可以附，寫明只照它的配置與造型，鏡頭照正面俯視規則；不附 style_ref。
- 要動的部分分層生（藥局配藥櫃：櫃體、取藥爪、玻璃各一層），同畫布對齊。
- 直接生、給使用者挑物件（不用先看 prompt）。實際送出的 prompt 寫進 `tools/art/<場景>/prompts.md`。

### 5. 切圖，交給使用者排
- 切圖：`python tools/art/cut.py props <場景> <批次|all>`（表寫在 `<場景>_objects.py` 的 `sheets()`；並排太近被併成一件就調 `JOIN`，有玻璃的批次放 `KEEP_ALPHA`）。物件切成 **2 倍尺寸**（一格 96），map.json 用 `scale: 0.5`。
- 去背檢查洋紅殘留要是 0。數量對不上 `cut.py` 會報錯，不要猜。
- 全尺寸去背 PNG 放到 `場景/<區>物件/` 給使用者（同一夾附一張「底圖位置.png」：遊戲底圖裁那一區、放大 2 倍，拉進 PSD 當「底圖位置」圖層）：使用者在 PSD 修細節、排位置與大小（PSD 裡放一層「底圖位置」＝遊戲底圖，用來換算座標）。`場景/` 是使用者的資料夾，只放交給使用者的檔案，不整理、不刪。

### 6. 匯入擺放
- 匯入：`python tools/art/cut.py psd <場景> <PSD 路徑>`。程式用影像比對找出「底圖位置」圖層在遊戲底圖的位置與倍率（相似度低於 0.8 會停下，表示底圖改過、要重放一層），把其他看得見的圖層匯出成 2 倍 webp 到 `public/assets/<場景>/props/`（檔名＝圖層名括號前那段），每件的世界座標存成 `tools/art/<場景>/layout_<PSD 檔名>.json`。要跟另一層同畫布的（玻璃墊到櫃體）寫在 `<場景>_objects.py` 的 `CANVAS`。
- `PLACE` 從 layout 讀位置（醫療室的 `at('圖層名')`），碰撞自己填格數。使用者改 PSD 後：重跑 `cut.py psd`、再跑場景的地圖腳本就好，不用手改數字。
- 擺進地圖：decor 以**底部中心**對齊；圖層與碰撞照下方「圖層與碰撞規則」，擺完照檢查表走一次。
- 互動（`INTERACTIONS`）：點擊範圍＝整張圖；站位要測過走得到、離圖 ≤ 48 px（互動範圍 56 px 以內）、不在縫裡。坐、躺用 interaction 的 `seat`（相對圖的位置）。
- GM 物件清單：在 `src/game/facilityContext.ts` 補中文名稱。
- 不要跑使用者正在改的場景的 build 腳本（會蓋掉使用者改的底圖）；要驗證就跑測試或在暫存區合成。

### 7. 收尾
- 原圖放 `tools/art/<場景>/raw/`，prompt 寫進 `prompts.md`；試錯檔放暫存區（`starport-asset-gen` 第七節）。
- 更新 `docs/scenes/<場景>.md`、`docs/PROGRESS.md`；有修正問題就更新 `問題修正紀錄.md`；使用者說可以再 commit。

## 圖層與碰撞規則

物件「蓋住角色」「角色穿進物件」「影子壓到物件」都是這裡的規則沒照做。數字以設施場景的角色為準（`ACTOR_HEIGHT` 148）；換角色尺寸或在房間場景（腳圈半徑 14）用，照公式重算。

**角色尺寸**：腳點是畫面座標的基準。腳圈半徑 22（碰撞）；影子是腳點上方 3 px、半寬 23、半高 7 的橢圓；頭寬 72（半寬 36，全身最寬的地方）；頭頂在腳點上方約 140 px。

### 一、圖層（誰畫在誰上面）

遊戲每一幀照「腳點的高低」重排（Y 排序）：物件的腳點是**圖的底邊**，角色腳點比物件底邊低（畫面更下方）就畫在物件前面。

1. **一張圖只能有一個底邊。** 有一部分是角色能站在它「旁邊」、腳點卻比整張圖底邊高的（L 型、U 型櫃台、圍一圈的沙發、前後兩段不一樣深的機台），拆成幾張圖，每段各有自己的底邊。拆法：使用者在 PSD 分成不同圖層，或寫在 `<場景>_objects.py` 的 `LAYERS`（crop／clear／keep）讓程式拆；不要手動改像素。
2. **同一件物件的疊層**（櫃體→動畫零件→玻璃、床→被單）：同畫布、同中心，用底邊差 0～1 px 決定順序（同底邊時照 PLACE 的先後）。
3. **躺、坐**：角色改用家具的排序線（interaction 的 `sortY`），要蓋在角色身上的那層（被單、近側扶手）底邊比家具多 1 px。
4. **左右兩側**（`beside`）：角色腳點在圖的左右範圍外時畫在物件前面。**程式照圖自動判斷，不用逐件標**（`decor.ts` 的 `baseOverhang`／`besideByShape`）：圖往兩側懸空伸出（整張圖寬 − 底部 15% 那段的寬，取較大一邊）不超過 24 世界 px 的算並排（桌、櫃台、床、沙發、櫃子、石頭），超過的照腳點排（樹冠：角色站在樹冠底下要被蓋住）。自動判錯時才在 map.json 的 decor 寫 `"beside": true／false` 蓋過去。只補矮桌側邊這種情況，**不能拿來代替第 1 條的拆圖**。兩件物件的圖疊到時一律照底邊排，`beside` 會打亂這個順序時程式自動不套用（`sceneDepth.ts` 的 `underPlayer`）。
5. **永遠在上**（門楣、牆簷、吊燈、天花板管線）：前景層（overlays／walls），不參與排序。**永遠在下**（地毯、地貼、地上的線）：畫進底圖，不當物件。
6. 原則見 問題修正紀錄.md「牆與遮擋」，各場景數值見同檔「待搬移的場景數值」（之後會搬到 docs/scenes/<場景>.md）

### 二、碰撞（腳能走到哪）

碰撞一律用精細矩形（collisionRects，格為單位），不用整格；規劃圖的佔位格在物件擺好後改由圖給（醫療室的 `PLAN_FROM_ART`）。

**物件碰撞一律由 `tools/art/footprint.py` 照圖算**（三個設施共用，下面 1–3 條都在裡面）：每件物件只要給「在地上佔多深」（`depth` 格，或醫療室 `PLACE` 的手填範圍），左右寬度與往上撐的量由圖決定。只給 `depth` 的物件**沿著圖的輪廓**切成窄直條（`outline`）：正面照每條圖的底邊（弧形沙發中間內凹、圓桌兩側收窄），背面是「底邊往上 depth」與「那條圖頂往下 92 px」取較靠後的（椅背是弧形，背面就是弧形）。`depth` 給到背面該到的最深處就好，給太大角色會靠不近（例：沙發 0.5 格，站在椅背後面時下半身被擋住、頭肩露出）。算出的矩形帶 `of`＝物件 id，用 id 對應，不靠排列順序。各場景的入口：醫療室 `medical_base_v9.py`、工程區 `engineering_build.py`、溫室 `greenhouse_collision.py`（擋路的 decor 要有 `id` 和 `depth`；種植架 `racks` 也照外框圖算，`of` 是 `rack-x,y`，不再用整格擋；移動物件、換圖、改 depth 後重跑）。沿著輪廓的物件，遊戲排前後時用角色腳下那一段的底邊（`sceneDepth.ts` 的 `frontOutline`），跟碰撞同一條線，站進凹處不會被蓋住。**不要手改 map.json 裡帶 `of` 的矩形**，重跑會蓋掉。

1. **左右：圖在碰撞那幾列的實際寬度外 3 px**（影子半寬 23 − 腳圈 22 ＋ 留白 2）。程式自動撐寬（`SHADOW_GAP`），手填的只要大概對。
2. **下緣：圖的底邊**（物件貼地的那條線）。角色從前面靠近時影子上緣離底邊 12 px，不會壓到。
3. **上緣：物件在地上實際佔的深度，但最低只能到圖上緣往下 92 px**（角色高 140 − 露出頭肩 70 ＋ 腳圈 22）。角色站到物件背後最深處時，頭和肩一定露在物件上面，不會整個人不見。矮物件自然符合；高物件（櫃子、機台）程式會把碰撞往上撐（`SHOW_DEPTH`）。樹冠這種往兩側懸空的物件（判斷同第一節的 `beside`）不撐，角色要能走到樹冠底下。撐完背後剩下的走道不到 72 px 的，靠牆擺或碰撞直接接到牆，不留縫。
4. **直牆內側多擋 14 px**（頭半寬 36 − 腳圈 22），貼牆時頭才不會凸進牆裡。門洞兩側不加，門不會變窄。程式自動加（`HEAD_PAD`）。
5. **走道寬**：兩件物件之間要讓人走過，淨寬至少 1.5 格（72 px，＝頭寬）；只要能鑽過去的縫（腳圈 44 px 以上、頭寬以下）會讓頭跟兩邊物件重疊，寧可堵死。
6. **站位**（互動、NPC、躺坐後起身的點）：程式挑或測試檢查「走得到」，不要只靠眼睛看；起身點要在碰撞外。

### 三、擺完的檢查表

- [ ] 每件物件都試站四個位置：正前方貼著站、左右兩側貼著站、能走到的話站在後面。前面看得到全身與影子、旁邊不被蓋臉、後面只蓋下半身。
- [ ] 影子在任何位置都不壓到物件；頭不凸進直牆。
- [ ] 有 L 型、U 型、前後兩段的物件都拆了圖。
- [ ] 站到高物件背後最深處還看得到頭肩；背後走道淨寬 ≥ 72 px，不然堵死。
- [ ] 場景測試補上：物件擋住、站位走得到、可躺坐的物件「家具在下、被單在上」。
- [ ] 用離線合成（照遊戲的順序：before 的物件 → 角色 → 其他物件，一次只放一個角色）或瀏覽器實際走一圈截圖給使用者看。

## Codex 生圖

- **不用先給使用者看 prompt**（2026-10-26 使用者定）：直接生，生好的物件表給使用者挑要用哪幾件。每次 2–5 分鐘，一批把同一區的候選物件畫在同一張表，挑完再切。
- 指令（在專案根目錄執行，prompt 從 stdin 送；開頭先寫給 Codex 的指示：照附圖生成、存到 `tools/art/<場景>/raw/<檔名>.png`、生完用看圖工具自我檢查、不合格重生最多 3 次）：

```
codex exec -s workspace-write -i <image1> -i <image2> - < <暫存區的 prompt 檔>
```

- 命令列版 `codex` 跟 Codex 桌面版是分開安裝的；桌面版更新了、命令列版沒更新時，新模型會被拒（「not supported when using Codex with a ChatGPT account」），先跑 `codex update`，或用 `-m` 指定舊版認得的模型。
- 2026-11-23 起用 `gpt-6.2-sol`（使用者：6.1 最近能力變差）。命令列版 0.163 不認得 6.2、`codex update` 也裝不起來時，改用 Codex 桌面版附的較新 CLI：`$LOCALAPPDATA/OpenAI/Codex/bin/<hash>/codex.exe exec -m gpt-6.2-sol ...`（`<hash>` 資料夾會隨桌面版更新變）。
- Codex 偶爾生完存不進專案（檔案工具故障），原圖會留在 `~/.codex/generated_images/<session>/`，從那裡複製。

- 回傳的圖不一定是 1024（常給 1254）；切圖座標一律依圖寬等比例換算。

## 踩過的坑

| 症狀 | 原因 | 做法 |
|---|---|---|
| 物件斜放、看得到側面，放不進地圖 | 鏡頭規則沒寫在最前面，或叫模型「照範例圖」連鏡頭一起抄 | 正面俯視規則放在 prompt 設計段之前；參考圖寫明只照造型 |
| 物件扁扁的、只有一條薄頂面，每件都像櫃子 | 用程式白模定視角或造型 | 不用白模；用文字描述造型＋風格參考圖 |
| 物件乾淨但看起來很中古（工程區 batch20） | prompt 只寫 clean / no rust，又拿舊設計表叫模型照抄 | 寫出它做什麼、科技感在哪＋禁止項 |
| 成品很空、不像該物件、太寫實、整批長得一樣、有光暈 | prompt 沒照範本（禁止項太多、沒給關鍵字、寫死材質、附了參考圖） | `starport-asset-gen` 第五節 |
| 整區畫好再切，物件互相黏住、背後缺一塊 | 把整區設計稿當素材切 | 設計稿只當參考，物件單獨生（第 3、4 步） |
| 改了原圖，遊戲裡還是舊的 | 改完沒重切 | 改 raw 表要重跑 `cut.py`；改 PSD 要重新匯入 |
| 一件物件被切成兩件，或兩件被併成一件 | 並排物件的間距跟併塊距離不合 | 調 `<場景>_objects.py` 的 `JOIN` |
| 切圖邊緣一圈紫紅 | 洋紅混色 | `cut.py` 去背，檢查殘留為 0 |
| 牆邊長條物件下半部露出地板（隱形牆） | 圖的高度蓋不滿佔地 | 依圖的實際大小定佔地，不要為了填滿佔地拉長物件 |
| 角色臉被 L 型櫃台的短邊蓋住 | 整張 L 只有長邊一個底邊 | 拆圖（圖層與碰撞規則一-1） |
| 影子壓到桌腳、頭凸進牆 | 碰撞只算腳圈，沒算影子和頭寬 | 規則二-1、二-4（程式自動） |
| 走到櫃子後面只剩頭髮 | 碰撞上緣照佔地深度給，背後走道太深 | 規則二-3（程式自動） |

| 終點格中心被精細碰撞蓋住就找不到路 | 尋路只走格子中心 | facility.ts 的 findPath 已改成：任一格中心能直線走到終點就算到 |

| 跑了 build 腳本，使用者改的底圖被蓋掉（工程區 2026-10-17） | build 會重寫 public/ 的底圖 | 不跑使用者正在改的場景的 build；驗證用測試或暫存區 |

## 瀏覽器測試小技巧

側邊瀏覽器面板隱藏時 `requestAnimationFrame` 不會跑，畫面不更新。測試時先在頁面執行
`window.requestAnimationFrame = cb => setTimeout(() => cb(performance.now()), 16)`，
再截一次圖讓迴圈接上。
