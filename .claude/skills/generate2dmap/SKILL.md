# 星際港場景地圖流程

改編自 agent-sprite-forge 的 generate2dmap（MIT，見 `LICENSE`）。原版涵蓋橫向捲軸、tilemap 引擎、戰棋格、等角棋盤等多種地圖；本專案只用「分層底圖＋獨立物件＋另外定義碰撞」這一種，其餘已刪除。

一句話：**底圖只放不動的結構，會跟角色互動或排前後的東西一律分層；碰撞寫成資料，不從圖推。**

## 本專案的地圖長什麼樣

- 斜俯視 RPG 視角，React canvas 自己畫，不輸出 Tiled、LDtk、Godot 這類引擎格式。
- 美術圖塊一格 48 × 48 px；新場景的 map.json `tileSize` 也用 48（醫療室起，2026-10-15 使用者定）。舊場景（溫室、工程區等）仍是 96。角色身高固定 148 世界單位（`src/game/viewport.ts` 的 `ACTOR_HEIGHT`），一格 48 時角色約 3 格高。格式定義在 `src/game/facility.ts` 的 `FacilityMap`。
- 每個場景放在 `public/assets/<場景>/`：

| 檔案 | 內容 |
|---|---|
| `ground.webp` | 底圖：地板、外牆立面、下方走廊。只有不動的結構 |
| `props/*.webp` | decor：室內牆、家具、機台，以底部中心對齊，依底邊 y 跟角色排前後 |
| `door_frame.webp`、`door_left.webp`、`door_right.webp` | 自動門的門框與兩片門扇，程式控制開關 |
| `wall_cap.webp`、`foreground.webp` | 前景：牆簷、欄杆，永遠蓋在角色上面 |
| map.json 的 `walls` | 室內橫牆牆頂那一條（從 ground.webp 切 rects），依 bottom 跟角色排前後，角色在牆端左右之外不被蓋。範例：醫療室 `medical_base_v9.py` 的 `collision()` |
| `map.json` | `collision`、`collisionRects`、`entrances`、`door`、`foreground`、`decor`、`interactions` |

- 畫的順序：底圖 → decor 與角色依底邊 y 排序 → 門 → 前景 → UI。
- `map.json` 由 `tools/art/<場景>_build.py` 產生，**不要手改**；要改就改腳本或規劃檔再重跑。

## 分工

- 使用者：定格局方向，看規劃圖、prompt 和參考圖後拍板。
- Claude Code：規劃腳本、開派工單、拼接底圖、碰撞與 map.json、接進場景、驗收。
- Codex：只生圖（素材套件、擺設參考圖、最終物件），照 `docs/tasks/` 的任務單交件。

## 流程

### 1. 先討論格局

- 動手前先問使用者：要哪些分區、各放哪、多大。使用者給方向後才畫。
- 依這個地方的功能和動線分區（東西從哪進來、在哪處理、人在哪休息），不要照搬別的場景格局。
- 討論結果寫進 `docs/scenes/<場景>.md`。

### 2. 規劃圖

- 寫 `tools/art/<場景>_plan.py`：用字母格（`LAYOUT`）描述牆、門、分區，產出規劃圖 png 與 json，並檢查連通、窄道、死路。範例：`tools/art/medical_plan_v9.py`、`tools/art/plaza_plan.py`。
- 牆要畫成實際佔的列數（走廊牆 4 列、醫療室一般內牆 4 列），不能簡化，不然比例對不上。
- 規劃圖給使用者確認後才進下一步。

### 3. 素材套件（Codex 生圖）

- **不叫模型一次畫整張底圖**。底圖由腳本從素材套件拼出來，牆線、門洞才會跟規劃圖對齊，改格局也只要重跑腳本。
- 素材套件通常是：每種地板一張（正俯視、填滿畫面、可無縫重複）、牆的樣板（牆頂、牆面、轉角）、有特色的牆面（例：休息區北牆）。
- 開派工單 `docs/tasks/T<n>-<場景>-<內容>.md`：每張的檔名、尺寸、完整 prompt、共同風格段、交件位置。
- 畫風、配色、光源照 `starport-asset-gen`：HD 像素風，派工單的共同風格段用它第一節的風格段，再接區域材質。年代是 2090 年（`docs/world.md`），不要紙本、文字、標誌。場景特例看 `docs/scenes/<場景>.md` 與 `問題修正紀錄.md`。
- 地板和牆的素材另外寫明：表面低對比、少雜訊，之後擺上去的家具才看得清楚；像素尺度跟物件一致。
- 原圖放 `tools/art/<場景>/raw/`，prompt 寫進 `tools/art/<場景>/prompts.md`（檔案規則見 `starport-asset-gen` 第六節）。
- 整張畫不下時可以讓 GPT 分塊「照描＋加質感」重畫拼好的底圖（醫療室作法見 `tools/art/medical/prompts.md`）：只准加質感、不准動牆線，生完比對牆面上下緣；放手讓它畫，牆面會縮短，碰撞就對不上。
- 生圖前先把 prompt 給使用者看，說可以才送（使用者在意成本）。

### 4. 拼接底圖與結構（build 腳本）

`tools/art/<場景>_build.py` 讀規劃 json，把素材套件切割、縮放、無縫化、組牆，輸出 `ground.webp`、牆的 decor、門、前景、`map.json`，另存 `tools/art/<場景>/base_full.png`（全部疊起來的底圖，給擺設參考圖用）。範例：`tools/art/medical_base_v9.py`（從使用者給的素材圖切拼，一格 48）、`tools/art/engineering_build.py`；下方走廊沿用 `public/assets/corridor-a` 素材。

分層規則：

- 底圖**只能有**：地板、地面標線、外牆立面、走廊等不動、不互動、不必跟角色排前後的結構。
- 底圖**不能有**：家具、機台、門、要跟角色排前後的室內牆、會蓋到角色的牆簷與欄杆、可互動的東西、角色、文字與 UI。
- 生出來的圖把上面這些畫進去了，就不能當底圖：重生，或只拿來當參考。
- 程式只做切割、縮放、無縫化、拼接、去背，不用程式畫最終美術。使用者明說要白模或暫代圖時例外（工程區室內目前仍是程式畫的暫代材質）。

牆與遮擋的數值（腳點能走進牆頂多深、前景蓋多高、室內牆牆頂厚度、直牆上的門開在哪）照 `問題修正紀錄.md`「牆與遮擋」，不要另訂。

### 5. 碰撞、出入口、門

- 碰撞跟圖分開定義，不從圖的透明區域推。
  - `collision`：整格的 0／1 表。
  - `collisionRects`：精細矩形（格為單位），給薄牆、物件底部這類不到一整格的東西。
- 物件只擋佔地（底部往上 depth 格），不擋整張圖的輪廓。
- `entrances`：邊界上的格子區＋通往哪裡（`to`）＋從那邊進來時的出生點（`spawn`）。場景相接靠角色走到邊界，入場朝向順著行進方向。
- `door`：門洞格（`passage`）、門扇範圍、門框圖、警示燈位置、自動關門距離，見 `DoorSpec` 的註解。
- `interactions` 的站位用程式挑，不手填（作法見 `starport-scene-props` 步驟 5）。

### 6. 家具與機台

照 `.claude/skills/starport-scene-props/SKILL.md`。那份流程沿用以下兩條原則：

**擺設參考圖**

- 底圖要真的當圖片交給模型（Codex 用 `-i`），不能只在 prompt 寫檔名。
- prompt 明講：照這張底圖，保留鏡頭、構圖、尺寸、地板與牆，只加物件。
- 物件畫成遊戲裡的樣子，不畫圈、箭頭、框線、標籤、文字、數字等標註。
- 每張參考圖最多 9 種不同物件，物件多就分區分張。
- 參考圖只是規劃用：不當底圖，也不從參考圖直接切物件。

**物件分類決定生法**

- 小型雜物（箱子、桶子、盆栽、小燈）：可以 3 × 3（或 2 × 2）一張表，每件只佔格子中央 50–60%。
- 長條的（牆邊長櫃、長桌、欄杆）、高大的（機台、大型櫃、門）、要對齊碰撞或門洞的：一件一張；同類的高物件可以同一張並排，格子留大。
- 同一張表不混放：小雜物表裡不放長條、高大、要對齊碰撞的東西。
- 表裡某件碰到格邊：不要放寬檢查硬過，改成一件一張重生。

### 7. 驗證

地圖檢查（規劃腳本、場景測試、瀏覽器各看一次）：

- 每個入口的出生點站得到；所有空地從入口走得到。
- 門洞中間走得過，門關著時擋得住；牆、門柱擋得住。
- 互動物件底部擋人，但站位走得到、按 E 有反應。
- 角色在高物件前後走過時前後順序正確；站在牆後時牆簷蓋到胸口以下；從桌子側邊經過時頭不被蓋住。
- 改了圖就重跑 build 腳本，碰撞、decor 座標、測試一起更新。

程式檢查：

- `npm run lint`、`npm run build`
- 改到的邏輯對應的測試，例如 `node --import tsx src/game/facility.test.ts`、`src/game/decor.test.ts`、`src/game/sceneDepth.test.ts`
- 瀏覽器實際走一圈（側邊面板隱藏時畫面不更新的處理見 `starport-scene-props` 最後一節）。

### 8. 收尾

- 更新 `docs/scenes/<場景>.md`、`docs/PROGRESS.md`；有修正問題就更新 `問題修正紀錄.md`。
- 當天任務完結後才 commit 並 push。

## 不要做的事

- 叫模型一次畫出含家具的完整地圖，再從裡面切物件。
- 拿擺設參考圖或預覽圖當 `ground.webp`。
- 用透明圖的外框當碰撞。
- 手改 `map.json`。
- 在這個流程裡生角色、NPC 素材：角色看 `docs/characters.md`。
