# 地圖編輯器的標註

這裡放 `../../../../工具/地圖編輯器_v3.html`（專案根目錄的 `工具/`，不在 repo 裡）匯出的 `interactions_<PSD 檔名>.json`。

## 流程

1. 在 Photoshop 排好場景物件（要有一層「底圖位置」）。物件要有互動狀態圖的話，另放一層「`<物件名>@互動`」，可以藏起來。
2. 用地圖編輯器開這個 PSD：
   - 選物件 → 右側「這個圖層是」選「互動物件」，填互動類型、顯示名稱、互動文字、效果備註；用「站位」工具點角色互動時站的地板。
   - 碰撞預設自動算（見下面「用 PSD 拼場景」）；自動的不合用才選著物件按 C 拖曳手畫，碰撞會掛在這件物件下（其他東西變暗）。
   - 圖層名稱可以在右側改；不會改 PSD，匯出時記下改名，`cut.py psd` 照新名稱存圖。
   - 工具列「場景」填 `public/assets` 底下的資料夾名（`medical`、`rooms/lucian`…）。
3. 「匯出 JSON」，存到這個資料夾。
4. `python tools/art/cut.py psd <場景> <PSD>`：切圖（含 `-active` 互動狀態圖）並記下 PSD 在遊戲底圖上的位置。
5. `python tools/art/editor_layout.py <場景>`：把互動、碰撞、互動狀態圖寫進 `public/assets/<場景>/map.json`。可以一直重跑，同一份 PSD 上次寫的會先清掉。各場景產生 map.json 的腳本也會自動套用，重跑場景腳本不會弄丟。

## 用 PSD 拼場景（自動擺放）

工具列「自動擺放」勾著（預設）時，PSD 裡每個看得見的圖層＝一件物件，不用另外寫擺放位置、不用畫碰撞：

| 圖層 | 怎麼進遊戲 | 碰撞 |
|---|---|---|
| 矮的（圖高 ≤ 92 世界 px）、不互動 | 併成一張 `<PSD 檔名>-ground.webp`，一直在角色底下 | 整張圖擋 |
| 高的（> 92 px） | 單獨一張圖，跟角色排前後 | 底邊擋到圖頂往下 92 px，角色走到後面下半身被蓋住 |
| 會互動、有「@互動」狀態圖 | 單獨一張圖（要換圖） | 同上（矮的整張擋） |
| 矮的但疊在單獨一層的物件前面 | 單獨一張圖（併進地面會被蓋住） | 整張圖擋 |
| 設「不擋」的（地毯、地貼） | 照上面分 | 沒有 |
| 有手畫碰撞的 | 照上面分 | 用手畫的 |

- 碰撞背後剩不到 72 px（頭寬）就自動往上接到牆，不留只夠鑽的縫；手畫的也一樣。
- 編輯器裡紫色虛線是自動碰撞的預覽，圖層清單標「地面」「自動」「不擋」。預覽照工具列的「PSD 倍率」換算，以 `editor_layout.py` 跑出來的為準。
- 場景腳本已經擺過的圖層（例：醫療室藥局 PSD 的配藥櫃、L 型櫃台的原圖）不動，照場景腳本的；新加的圖層才自動擺。
- 跑 `editor_layout.py` 會列出每件怎麼分、為什麼。

## 先畫個大概也可以

編輯器常常先拿來畫大概，標一半就匯出沒關係：能進遊戲的先進去，沒做完的在跑腳本時列成「還沒完成」清單。

- 沒寫互動文字：照樣寫進去，按了不冒文字；沒取顯示名稱就先用圖層名。
- 物件還沒擺進場景：互動和碰撞先照畫的位置寫，碰撞暫時不掛在物件下（`layer` 記著是哪件），擺好後重跑才掛上、跟物件排前後。
- 站位在碰撞裡：這個互動**先不放進遊戲**（走不到也點不到，遊戲測試也會擋），站位改好重跑就會進去。
- 門／坐下／躺下、出口沒填目的地、上傳的互動狀態圖：照樣寫，清單提醒還要補什麼。
- 工具列「場景」空的或填錯：不會套到任何場景，跑腳本時會提醒。
- 碰撞照畫的位置擋路：畫得太大把某塊地封死的話，`src/game/facility.test.ts` 的「每塊地都走得到」會擋下來。

## 遊戲裡的效果

- 綁了擺設的互動（`interactions[].decor`）：按 E 或點它，那件擺設換成互動狀態圖（`decor[].active`）；走開或再按一次換回。坐下、躺下時一直是互動狀態。
